# Windows control contract

Before editing Windows UI, read [the detailed specification](../../docs/design/windows-controls.md). This rule supersedes older blanket pill-button and segmented-filter guidance **for Windows**. Preserve the Android host's existing implementation unless Android changes are explicitly in scope.

1. Use `desktop/ui/controls/DesktopControls.kt` for desktop action buttons, outlined inputs, search, filter/choice rows, icon buttons and quick-access tiles. Reuse shared Aurum colors, `ButtonShape`, typography and motion; never make a local lookalike or hide an icon to fit a label.
2. **Header**: action/date/connection/back capsules are 24dp radius and 48dp height. Identity and registration/back actions belong to `WorkspaceHeader`. At narrow widths, actions stay beside identity; status may occupy a second header row. **Navigation** keeps its existing rounded treatment. Do not use header capsules inside cards or dialogs except the explicitly approved compact rate-details navigation control below.
3. **Body/dialog actions**: `DesktopActionButton`, 12dp `ButtonShape`, 48dp height (44dp minimum for dense tables), 14sp Vazirmatn label, 20dp meaningful icon, one line, 6dp icon gap, 12dp horizontal padding. An icon is a required argument. Secondary actions use elevated surface/hairline; primary actions use the existing gold gradient. Preserve disabled/loading/busy behavior. Cancel remains first/right in RTL.
4. **Filters**: `DesktopFilterRow`/`DesktopFilterChip`, independent selectable capsules based on Android `LedgerFilterCapsuleItem`; no enclosing segmented track/sliding pill. Use separate count badges, correct existing single selection behavior, 48dp target, 14sp text, keyboard selection/focus, overflow scrolling, 200ms color transitions (zero with reduced motion). Record-status, inventory category/custom category and rate-instrument filters use this rule. **Approved retained selectors**: dashboard chart horizons (32dp/10.5sp) and rate chart horizons (38dp/11sp) use shared `LuxurySegmentedControl` with its previous sliding indicator. Customer account type has no Windows display/selector; retain legacy stored roles when editing. Inventory location uses a Store/expand dropdown in the search toolbar, never chips. Other **form choices** use `DesktopChoiceRow` with 12dp body curvature; calculator calculation modes also retain their approved controls.
5. **Search**: `DesktopSearchField`, 12dp radius, 48dp height, search icon, one-line 14sp text, clear control when nonempty, visible focus outline. Form inputs use `DesktopOutlinedTextField` or `DesktopField`/`GoldInputField` which delegate to it, also 12dp. Keep floating labels transparent, numeric text LTR/ss01 and units at visual left. Dropdown fields use the same body shape and an expand icon.
6. **Dashboard shortcuts**: icon-above-label `DesktopQuickAccessTile` derived from Android banking quick access; retain destinations and keyboard interaction. Do not turn these into stretched primary/secondary buttons.
7. Audit every rendered action, including empty/error states, old holdings, forms, delete confirmations, settings, signature/image controls and updater. Record approved exceptions and changed coverage in the specification. Verify minimum window, wide window, light/dark, keyboard, filter semantics, labels without overflow and financial workflows. Add meaningful guard coverage so future features cannot silently reintroduce raw mismatched controls.

8. Both dashboard card links («دفتر فاکتورها» and «همه نرخ‌ها») use `DesktopNavigationLink`: transparent text link, gold 12.5sp label and 16dp directional icon, no filled/outlined action container. Destinations remain INVOICES and RATES. The rate board's «جزئیات» uses `DesktopRateDetailsButton`: 32dp-high capsule, 12sp label, 16dp auto-mirrored forward arrow after the label (visual left and pointing left in RTL). Footer ticker previews retain their original 20dp capsule, 10dp/3.5dp horizontal/vertical padding, 11sp title and 11.5sp value, no chart icon or 44dp forced height; each passes its explicit `BoardInstrument` to `DesktopWorkspace.openRateDetail`. These preview/navigation exceptions do not apply to save/delete actions.
9. Wide settings use equal-height profile/preferences columns; the rate-source card fills the space below calculation defaults so its bottom aligns with the gallery profile card. Its explanatory note sits at the bottom padding, with excess space distributed between heading, source options and note. Measure natural children so content contraction releases extra height. Narrow settings stack at natural heights. Dashboard phone-sync disclaimer is omitted; this does not add synchronization.
10. Icon-only actions keep a minimum 44dp target and circular Material hover/ripple/focus; never add a rectangular hover background behind them. Customer toolbars fill available width: filters wrap their content up to the scroll limit and search fills the remaining width, with a 12dp gap and equal 48dp heights. Rate statistics use 18sp title, 13sp table headings/values, 12sp evaluation/note, and a compact footer with 8dp top padding/3dp line gaps; source, cached status and errors remain visible.
11. Customer cards show name and account-status badge in one row, phone and optional account code in parentheses beneath; no role, activity date, repeated contact row or missing-code placeholder. Preserve all user data. Actions retain explicit full labels: «ثبت دریافت/پرداخت» full width, then «ریز گردش» / «ثبت فاکتور» side by side, all 14sp with icons. The invoice action opens the real invoice editor with that customer selected. Responsive reflow must preserve complete action labels.
12. App-owned dialogs/confirmations/sheets use `DesktopDialogHost` and the `DesktopDialog`/`DesktopAlertDialog`/`DesktopModalBottomSheet` adapters in `DesktopDialogs.kt`. Retain the outgoing display snapshot until exit finishes; saving/cancellation remains immediate in the feature owner. Use existing LuxuryMotion easing/duration tokens (dialog240/180ms, modal280/220ms), subtle .95→1 scale/fade for centered dialogs and 24dp translation/fade for sheets. Reduced motion makes the host transition immediate. Block pointer/keyboard/accessibility action input while outgoing; dismissal must not trigger a duplicate save/delete. Native Windows file/print pickers remain OS-owned.
